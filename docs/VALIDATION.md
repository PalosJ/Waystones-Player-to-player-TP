# 1.0.1 验收状态与证据规则

本文件登记玩法门禁，逐次构建与启动结果由候选证据记录。下表不将历史启动或旧文件的基本实测转记为新产物的玩法验收。最终提交后 minimum JAR 的源码提交、SHA-256、前置组合和日志由 `build/matrix-evidence`、`build/runtime-smoke-results` 与 release manifest 绑定；这些机器／产物相关记录保留在忽略目录或仓库外交付目录，不提交二进制或私人路径。

## 当前状态

- 已公开发布：正式 Modrinth 仅有旧 1.0.0 的 Fabric／NeoForge 1.21.1 文件。
- 用户历史基本实测：NeoForge／Fabric 1.21.1 原版本；不覆盖本次接收开关与新事务。
- 新 1.0.1 完整玩法、GUI 与性能验收：尚未完成。因此当前上传就绪列表为空。
- 26.1.1 还缺普通玩家可取得的匹配 Waystones 前置安装验收。

已尝试启动隔离 Fabric 26.2 current 专服与真实客户端：专服到达 Done，客户端完成资源加载；桌面 GUI 工具未识别 Java 应用（按应用名和 bundle ID 均返回 Invalid app），因此没有菜单点击／视觉结果。此限制只影响当前交互验收，不阻塞源码或启动验证。

纯 Java 稳定目录比较已对 50／200／1000 条目做同机旧基线与新源码微基准：两版算法源码相同，1000 条目中位刷新约 13 微秒、分配约 48 KB／次；50 条目的短测噪声较大，不据此声明帧率改善。测试不是完整客户端刷新，也不覆盖 GUI 帧时间与关闭后的对象释放，原始记录保留于本地验收证据。

## 必需记录

每个组合记录：源码完整提交、候选文件名／SHA-256、minimum／关键断点／current 的完整前置套件、测试日期、测试方式、日志或截图位置、通过／失败／未执行及原因。源码构建和客户端 atlas 启动不能替代真实菜单操作；开发期脏工作树产物不能当成最终提交来源证明。

玩法、GUI 和性能项目见 [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md)。需两个真实客户端与专服，集成服务器另做回归；所有原生石、主副手、三种经验模式、接收设置持久化、假人、移动／危险目标、取消／重定向／异常、普通 Waystones 隔离回归均需实测。1.21.2 与 1.21.3 必须用同一 JAR 分别执行。

性能报告应分别记录纯算法微基准和实际 GUI 帧时间。两者不可互相替代。真实 GUI 需含 50／200／1000 目录、不同宽度、100 次开关／缩放、默认皮肤延迟更新以及关闭后对象释放。

## 分支一致性

`scripts/verify-branch-parity.sh` 验证共享源码与记录的 canonical main 提交一致，并比较同系列加载器的公共适配族。它不验证原生控件、物品或事件行为。每个真实 API 家族仍需上表的独立运行与交互证据。
